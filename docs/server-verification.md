# Проверка установленного сервера

Дата: 10 ноября 2026 года. Среда: macOS / Apple Silicon, managed Wine 11.21, Kunos acServer v1.15 / protocol 202. Сервер импортирован из установленной Steam-копии игры; SHA-256 закреплён в `Scripts/runtime/server-manifest.json`. Серверные бинарники, игровые данные, prefix и журналы находятся вне репозитория.

## Выполнено

- Обычная `make-paddock-app.sh` импортирует сервер и устанавливает закреплённый Wine. Повторный запуск использует готовые зависимости. `.app` собрана и подписана ad hoc.
- Реальный интеграционный тест `MozaPaddock --server-live-check --server-check-address <LAN-IP>` запускает Lotus Elise SC / Magione на 19600 TCP/UDP и 18081 TCP. Через настоящий OnlineBrowser проверены INFO, JSON, pickup, модель машины и четыре свободных слота.
- Повторный live-прогон выявил ложное определение занятого TCP-порта после остановки (TIME_WAIT). Проверка теперь использует SO_REUSEADDR как Go-listener, сохраняя отказ для действующего слушателя; финальный live-прогон остановки/перезапуска и проверка занятого порта прошли.
- Тот же сервер ответил на loopback и LAN-адресе этого Mac. В журнале подтверждены checksums машины, трассы и общего system/data/surfaces.ini; отключения проверки surfaces больше нет.
- Через тот же ServerHost проверены подтверждённый статус готовности, остановка и повторный запуск с повторным использованием портов.
- В интерфейсе собранной `.app` проверены раскрытие навигации, форма, дополнительные параметры, создание Audi R8 V10 Plus / Interlagos GP, статус «Сервер готов», адресный просмотр с четырьмя свободными местами, переход между вкладками и остановка кнопкой. Для первого UI-теста использовались 19601 / 18082. Финальная сборка дополнительно проверена обычной кнопкой без изменения настроек: автоматически выбрала 9600 / 8082, подтвердила готовность, ответила через OnlineBrowser и остановилась.
- При GUI-проверке обнаружено зависание дочернего Python при чтении скриптов из Desktop-checkout. Серверные/онлайн-инструменты и чтение runtime status упакованы внутрь `.app`; повторный GUI-запуск сервера прошёл.
- Отдельный процесс пользователя занимает 8081. Он оставлен работать; мастер предлагает свободные начальные порты и проверяет их перед запуском.
- Офлайн-проверки покрывают закреплённый импорт, checksum, происхождение, повторную установку, повреждение cache, сохранность исходного сервера, откат конфигурации, общий surfaces, вместимость и порты. Live-тест не входит в CI.

## Что этим не подтверждено

Ответ на LAN-адресе проверен с самого Mac, а не со второго устройства. Внешний доступ через интернет и роутер не проверен: для этого нужны внешний клиент и настроенный входящий маршрут. Правила firewall, проброс портов и подписки провайдера не изменялись. Заезд игрового клиента и аппаратный FFB не запускались; MOZA во время GUI-проверки не подключена. Эти ограничения не следует выдавать за успешный вход игрока или полноценную сетевую гонку.

Каждый тестовый сервер остановлен после проверки. Для повторения используйте команды из [development](development.md); диагностические серверы не публикуются в общем лобби.

## Данные подключения — 11 ноября 2026

После создания сервер показывает адрес loopback, IPv4-адреса активных интерфейсов с настоящим HTTP-портом, игровой TCP/UDP-порт, машину, layout и состояние пароля. В GUI проверены отображение LAN/VPN-адресов, копирование адреса и приглашения, статус готовности и пометка данных после остановки. Приглашение не содержит пароль; он копируется отдельной кнопкой. Форма скрывается на время работы, чтобы данные подключения были видны сразу.

Self-test проверяет неизменность снимка конфигурации и отсутствие пароля в приглашении. Live-тест сверяет порты блока с реальным INFO сервера и проходит остановку/перезапуск. Дополнительно исправлен выбор порта при слушателе, привязанном только к loopback; сценарий покрыт локальной фикстурой. Финальный GUI-сервер ответил на выбранном свободном HTTP-порту и был остановлен. Внешние IP-сервисы и оборудование не использовались.
