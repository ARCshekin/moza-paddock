# Изолированная проверка CSP

Экспериментальная ветка; Alpine пока не считается стабильно поддерживаемой. Обычная Audi использует исходную библиотеку и Wine 11.21. Тестовые игровые файлы находятся в `MozaPaddock/Trials/assetto-csp`, отдельные графические среды — в `Trials/Runtimes`. Бинарники и пользовательские символы в Git не включаются.

## Что исправлено

`Bridge/csp-symbols.c` перенаправляет dbghelp в исходную библиотеку Wine и дополняет единственный запрос `SymEnumSymbols("acs!*")` символами локального `acs.pdb`. Генератор включает публичные символы и private data, возвращает читаемые имена переменных и folded functions. Таблица проверяется по GUID загруженного exe; для других запросов сохраняется исходное поведение. Все адреса генерируются локально.

Это развитие обхода [CSP issue 637](https://github.com/ac-custom-shaders-patch/acc-extension-config/issues/637), собственная реализация без включения стороннего исходного прокси. В реальном запуске CSP 0.2.11 нашёл все 2371 функцию.

Для отражения шейдеров нужен оригинальный `d3dcompiler_47.dll`: builtin Wine выдавал ошибку D3DReflect 0x8007000e. CAB Microsoft и извлечённый x64 DLL закреплены в `runtime/csp-directx-manifest.json`. Шрифты копируются только из локальной игры и macOS в тестовую папку `content/fonts/system`. Они не распространяются с проектом.

## Производительность и ограничения

`csp_performance.py` отключает необязательные графические модули, сохраняет резервные копии конфигов, оставляет разрешение экрана и физику. `play-csp-trial.py` запускает отдельную копию, временно подставляет race/video INI и восстанавливает их после выхода, управляет только своим процессом моста. Это диагностический запуск вне обычной записи рекордов Paddock.

Под DXVK Alpine загрузилась и пользователь видел около 60 FPS, но далее картинка замерла. Журнал подтвердил `VK_ERROR_DEVICE_LOST` в MoltenVK, при этом телеметрия физики продолжала обновляться. Повтор с отключённым DXGI flip model также потерял GPU. Уменьшение качества не подтвердило стабильность.

DXMT 0.80 прошёл тест создания D3D11 устройства на Wine 11.21, но создание окна Metal не удалось: отсутствуют необходимые экспорты драйвера winemac. Для следующего теста требуется совместимая отдельная сборка Wine. Не переносить тестовый backend в рабочую среду до проверки гонки.

## Офлайн-проверки

`python3 Scripts/check-csp.py` проверяет генерацию public/private data и сохранение посторонних настроек/резервных копий. `Bridge/tests/test_csp_symbols.c` проверяет Win64 ABI, флаги и типы символов, имена и GUID. Эти проверки не подтверждают GPU-стабильность.


## Совместимый Metal runtime

Для создания окна DXMT нужен драйвер с опубликованными Metal API. Используется свободный WS12WineSikarugir10.0_6 и DXMT 0.80; версии, официальные URL и SHA-256 из GitHub release metadata закреплены в `runtime/csp-metal-manifest.json`. Общие Unix-зависимости берутся из уже закреплённого локального Wine 11.21; Windows-модули той среды не подменяются. Новая среда использует собственный prefix, Steam и Documents. Direct3D smoke test пройден, игра запущена, подтверждение картинки и стабильного движения от пользователя пока ожидается.

Подготовка после закрытия заезда: `python3 Scripts/prepare-csp-trial.py`. Диагностический запуск: `python3 Scripts/play-csp-trial.py --renderer dxmt --hud`. Требуются уже подготовленные основная Wine/Steam-библиотека, локальная MOZA, Homebrew LLVM и lld. Это экспериментальный запуск, не замена обычной кнопки «Поехали». Копия Steam использует обычный вход и проверку лицензии; при запросе Steam Guard вход завершает пользователь.
