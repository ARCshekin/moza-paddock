# Свой сервер

## Быстрый старт

1. Соберите приложение: `./Scripts/make-paddock-app.sh`. Сборка автоматически импортирует закреплённый Kunos acServer v1.15 из локальной Steam-копии Assetto Corsa и устанавливает независимый Wine штатным проверяемым установщиком. Уже установленные зависимости повторно не скачиваются. CrossOver и игровой prefix не меняются.
2. Игра должна быть установлена в Steam. Paddock ищет сервер в managed Wine и бутылках CrossOver; поддержан также явный импорт `python3 Scripts/paddock-server.py install --root "<папка MozaPaddock>" --game "<папка игры>"`. Steam-файлы не скачиваются сторонним зеркалом и не распространяются внутри `.app`.
3. Откройте «Онлайн → Свой сервер». Выберите машину, трассу, layout, число мест и при необходимости пароль.
4. Нажмите «Создать и запустить»: приложение проверит установленный сервер и при необходимости повторит автоматический импорт. Ручной выбор acServer.exe сохранён в «Дополнительно» для собственного бинарника.
5. Дождитесь статуса «Сервер готов»: Paddock проверяет настоящий INFO и список слотов. Первый старт создаёт отдельный Wine prefix и может занять больше времени. При таймауте или ошибке откройте журнал.
6. На том же Mac подключитесь через «Онлайн → Каталог серверов → По адресу»: `127.0.0.1:8081` (либо заданный HTTP-порт). Друзьям в LAN передайте IP Mac и этот порт. Машина и трасса должны совпадать по версии.

Первый мастер поддерживает одну модель машины с упакованным `data.acd`, реальные скины и обычную тренировку от 1 до 240 минут. Вместимость не превышает число пит-боксов layout и 64 места. При отсутствии `surfaces.ini` трассы или общего `system/data/surfaces.ini` подготовка откатывается. Зоны DRS копируются, если они есть в трассе. Поддержка unpacked physics, CSP, AI-трафика и нескольких событий остаётся отдельной работой.

## Интернет и стоимость

Домашний сервер не требует обязательной аренды или платного менеджера; нужны собственная игра, включённый Mac и интернет. Опциональная публикация в лобби не настраивает сеть. По умолчанию используется частный LAN-сервер. При открытии мастера Paddock предлагает свободные порты начиная с 9600/8081. Если порт занят позднее, запуск сообщает ошибку и предлагает изменить его в «Дополнительно», не завершая чужие процессы.

На роутере и в firewall разрешите игровой порт 9600 TCP/UDP и HTTP 8081 TCP либо свои значения из «Дополнительно». Для друзей за пределами LAN используйте внешний адрес. При CGNAT понадобятся внешний IP у провайдера либо VPN, поддерживающий входящие соединения. Paddock не покупает услуги и не меняет роутер автоматически. Ссылка/адрес подключения не содержит пароль: передавайте его отдельно.

## Хранение и остановка

Каждое создание формирует новую папку `~/Library/Application Support/MozaPaddock/Servers/<UUID>`: копия установленного executable и соседних DLL, физические данные машины, surfaces трассы и общий system/data/surfaces.ini, `cfg/server_cfg.ini`, `cfg/entry_list.ini`, `server.log`. Исходный сервер и игровые INI не перезаписываются. Секреты находятся только в приватной серверной папке (0700, INI 0600); admin-пароль генерируется случайно и доступен в файле конфигурации. Серверные папки не входят в git и сохраняются после остановки; их можно открыть кнопкой «Файлы сервера».

`Scripts/paddock-server.py` использует закреплённую независимую Wine-среду и отдельный prefix `Prefixes/server`. Игровой prefix `Prefixes/assetto` и бутылки CrossOver не используются для сервера. Кнопка «Остановить» завершает только дочерний процесс сервера; если он не ответил на SIGTERM за пять секунд, завершается этот же принадлежащий приложению процесс. При обычном выходе из приложения также отправляется SIGTERM. При переключении вкладок процесс продолжает работать. Возобновление управления сервером после аварийного завершения приложения пока не поддерживается; для гарантированной остановки используйте кнопку перед выходом.

Ошибки Wine/занятых портов/бинарника отображаются в журнале. Счётчик игроков и автоматическая проверка доступности извне пока не реализованы. Результаты проверок реального сервера — [server-verification](server-verification.md); ответ на LAN-адресе с этого же Mac не подтверждает доступ с другого устройства или из интернета.


## Закреплённая установка

`Scripts/runtime/server-manifest.json` фиксирует Kunos acServer v1.15 / protocol 202 из Steam build 14923034, SHA-256, официальный источник и лицензионную атрибуцию. `runtime/server_install.py` принимает только совпадающий локальный файл, копирует его транзакционно в `ServerRuntime/<version>` и записывает `installation.json`. Повторная установка проверяет checksum; неизвестная или повреждённая версия не заменяется молча. Файлы Steam, игровые конфигурации и ранее установленные версии остаются на месте.

Для сборки без Steam и установки runtime используйте `./Scripts/make-paddock-app.sh --without-server`. Это явное исключение для офлайн-разработки, не режим обычной установки. CI компилирует Swift и проверяет установщик на фикстурах, не скачивая игру.
