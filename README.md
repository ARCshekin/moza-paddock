# MOZA Control для macOS

Минимальный аналог MOZA Pit House для macOS: калибровка центра руля, угол поворота
и сила отдачи. Написан для базы **MOZA R5**, проверен на живом устройстве
(macOS 14.3, Apple Silicon).

## Главное, что стоит знать

**Драйвер в смысле kext не нужен.** macOS уже видит базу как штатный USB-джойстик
(usage page 1 / usage 4), оси и кнопки работают в играх без какого-либо ПО. База —
составное USB-устройство:

| интерфейс | что это | как выглядит в системе |
|---|---|---|
| 0 + 1 | CDC-ACM, канал настроек | `/dev/cu.usbmodem*` |
| 2 | HID-джойстик: оси, кнопки, force feedback по стандарту PID | штатный `AppleUserHIDDevice` |

Поэтому это приложение — **утилита конфигурации**: настройки идут через serial-канал
(тем же путём, что у Pit House), а HID читается только для индикатора положения руля.
Вендорские HID-репорты (`0xAF`, `0x14`, `0x15`) не используются.

Устройство: VID `0x346e` (Gudsen), PID `0x0004` (R5 Base). Порт ищется по VID/PID
через IORegistry, а не по имени `usbmodem101`, чтобы переподключение не ломало работу.

## Сборка

Полный Xcode не требуется — достаточно Command Line Tools.

```bash
swift build                 # CLI: .build/debug/mozactl
./Scripts/make-app.sh       # GUI: build/MozaControl.app
```

## Использование

### Командная строка

```bash
mozactl selftest            # офлайн-проверка протокола, железо не нужно
mozactl list                # найти базу: serial-порт и HID-интерфейс
mozactl get --all           # прочитать все настройки и телеметрию
mozactl settings            # таблица известных команд
mozactl monitor 30          # живые оси и кнопки

mozactl angle               # текущий угол поворота
mozactl angle 540 --yes     # задать угол (90…2700, кратно 2)
mozactl ffb 70 --yes        # сила отдачи, 0…100 %
mozactl torque 90 --yes     # аппаратный лимит момента, 50…100 %
mozactl calibrate --yes     # калибровка центра (руль должен стоять ровно)
```

Всё, что меняет настройки базы, требует `--yes`. Флаг `-v` печатает hex каждого
отправленного и принятого кадра.

### Приложение

`build/MozaControl.app` — иконка в строке меню (в Dock не появляется). Внутри:
статус подключения, положение руля, ползунок угла поворота, кнопка калибровки,
ползунки силы отдачи и лимита момента, температуры. Ползунки пишут значение в базу
при отпускании, а не в процессе перетаскивания.

Разрешений macOS не требуется: serial-порт доступен как обычный файл, а HID-доступ
к джойстику не подпадает под «Мониторинг ввода». Приложение **не** в песочнице —
в песочнице IOKit-доступ молча не работает.

CLI и приложение могут работать одновременно: у них разные файловые дескрипторы,
а чужие кадры отбрасываются по несовпадению group и id.

## Протокол

Serial: `/dev/cu.usbmodem*`, **115200 8N1**, без управления потоком. Модель строго
request/response — база сама ничего не присылает, handshake не нужен.

```
[0x7E][length][group][device][id…][payload…][checksum]
  |      |       |       |                      checksum = (13 + сумма предыдущих байт) % 256
  |      |       |       device базы = 0x13
  |      |       группа: чтение/запись/действие
  |      length = len(id) + len(payload)
  start
```

- Значения — big-endian unsigned. Read-запрос отличается от write **только** байтом
  group и несёт payload = 1.
- В ответе `group` приходит с выставленным битом 7 (`40` → `0xA8`), `device` — с
  перевёрнутыми полубайтами (`0x13` → `0x31`), а **байт checksum присутствует и
  считается по той же формуле** (проверено на живом устройстве).

### Команды

| настройка | чтение | запись | id | байт | значение на проводе |
|---|---|---|---|---|---|
| `max-angle` | 40 | 41 | 23 | 2 | градусы ÷ 2 |
| `limit` | 40 | 41 | 1 | 2 | градусы ÷ 2 |
| `ffb-strength` | 40 | 41 | 2 | 2 | проценты × 10 |
| `torque` | 40 | 41 | 18 | 2 | проценты |
| `ffb-reverse` | 40 | 41 | 24 | 2 | 0/1 |
| `calibration` | — | 42 | 1 | 2 | 1 |
| `state`, `state-err` | 43 | — | 1, 2 | 2 | код |
| `mcu-temp`, `mosfet-temp`, `motor-temp` | 43 | — | 4, 5, 6 | 2 | °C × 100 |

Угол пишется **парой** `limit` + `max-angle` одним значением — только тогда база
применяет новый предел.

Примеры кадров (проверены на устройстве):

```
чтение max-angle          : 7E 03 28 13 17 00 01 E1
ответ (900°, на проводе 450): 7E 03 A8 31 17 01 C2 41
запись max-angle = 1080°  : 7E 03 29 13 17 02 1C FF
калибровка центра         : 7E 03 2A 13 01 00 01 CD
```

### Границы безопасности

Таблица команд в [MozaCommands.swift](Sources/MozaKit/MozaCommands.swift) —
единственный источник истины: код никогда не перебирает id и не отправляет ничего
вне этой таблицы. Команд обновления прошивки, записи EEPROM и сброса к заводским
настройкам в известной таблице нет, поэтому всё за её пределами — неисследованная
территория, и слепое зондирование живого железа недопустимо.

Перед записью значение проверяется на диапазон и на точную представимость: при
масштабе ÷2 нечётные градусы отклоняются, а не округляются молча. После каждой
записи выполняется контрольное чтение.

Источник разбора протокола — [boxflat](https://github.com/Lawstorant/boxflat) (GPL),
Linux-аналог Pit House. Кадрирование, контрольные суммы и масштабы значений
подтверждены на этом экземпляре R5: `mozactl selftest` сверяет кодировщик с
эталонными байтами офлайн.

## Чего нет

Остальные настройки Pit House (кривые отдачи, демпфер, трение, пружина, эквалайзер,
педали, дисплей, температурные стратегии) не реализованы. Все 51 команда секции
базы известны — добавление сводится к новым строкам в таблице команд.

## Force feedback

Отдача работает **напрямую через стандартный HID PID**, минуя подсистему Force Feedback
macOS: та с этой базой не работает вовсе — `FFIsForceFeedback` возвращает ошибку, а в
IORegistry устройству не сопоставлен ни один FF-плагин (исторически они поставлялись
внутри kext, что на Apple Silicon закрыто).

```bash
mozactl ffb-probe    # что подсистема macOS думает об отдаче (силу не подаёт)
mozactl ffb-test     # короткий импульс через HID PID, с измерением оси
```

### Главное правило транспорта

Буфер, передаваемый в `IOHIDDeviceSetReport`, **обязан начинаться с байта report ID**
(так же поступает hidapi). Для output-репортов это критично: они уходят в interrupt OUT,
где первый байт пакета и есть идентификатор репорта. Без него прошивка разбирает пакет
как другой репорт и молча его отбрасывает — `SetReport` при этом возвращает успех.
Feature-репорты идут управляющим запросом, где идентификатор передаётся отдельным
параметром, поэтому они «работают» и без байта ID, маскируя ошибку.

### Последовательность запуска эффекта

Повторяет рабочий драйвер Linux `hid-pidff`:

1. Device Control: сброс дважды → остановить все эффекты → включить приводы
   (поле объявлено как набор бит: `0x08`, `0x04`, `0x01`).
2. Device Gain (репорт 13) — общее усиление 0…255.
3. Create New Effect (feature 17) → Block Load (feature 18) выдаёт индекс блока.
4. Set Effect (репорт 1): **Gain в байте 10** — ноль здесь означает «без силы»;
   Trigger Button = 0; Direction Enable вместо бит осей; направление в сотых долях
   градуса.
5. Set Constant Force (репорт 5) — величина.
6. Effect Operation (репорт 10) — старт, затем стоп; Block Free (11) освобождает блок.

Направление задаёт **поле направления, а не знак величины**: 270° крутит ось в плюс,
90° — в минус. Проверено на железе.

### Особенность прошивки

Бит **Effect Playing** во входном репорте состояния (2) у этой базы не выставляется
никогда, даже когда эффект реально играет и вал крутится. Ориентироваться на него нельзя;
рабочий драйвер Linux его тоже не читает.


## Assetto Corsa через CrossOver

Добавлен Win64 DirectInput8-мост для оригинальной Assetto Corsa. Игра видит
`MOZA R5 Bridge`: X — руль, Y — газ, Rz — тормоз, кнопки 13/14 HID — левый/правый
лепестки (12/13 в `controls.ini`). Чтение HID и отправка силы используют MozaKit.
Мост передаёт настоящие эффекты DirectInput, а не восстанавливает их из телеметрии.

```bash
./Scripts/check-ac-bridge.sh             # DLL, C sanitizers, native effect/mapping checks
python3 Scripts/install-ac-bridge.py --bottle Steam-3  # игра должна быть закрыта
./Scripts/play-assetto.command           # Steam в этой бутылке должен быть запущен
./Scripts/stop-assetto-ffb.command        # остановить мост и снять отдачу
```

`play-assetto.command` запускает текущую тренировку из
`~/Documents/Assetto Corsa/cfg/race.ini` напрямую через `acs.exe`: штатный лаунчер
в текущей бутылке падает при загрузке CEF3 под Wine Mono. При прямом запуске нужны
`SteamAppId=244210` и `SteamGameId=244210`, иначе Steam возвращает запуск в штатный
лаунчер. Скрипт выставляет эти переменные только для запускаемого процесса.
По умолчанию используется бутылка Steam-3; другую можно выбрать через
`MOZA_AC_BOTTLE`. Скрипт использует установленный CrossOver, его лицензию не меняет.

Локальный `dinput8.dll` лежит рядом с `acs.exe`. Override `native,builtin` задан
только для `acs.exe`. Системные DLL Windows не заменяются. Драйвер ядра не нужен.
Windows-часть адаптирована из MIT-проекта crossover-ffb: исходник, commit и лицензия
сохранены в `Bridge/UPSTREAM.md` и `Bridge/LICENSE`. Идентификаторы и канал общей
памяти заменены на собственные; Logitech-команды на MOZA не отправляются.

Нативный процесс публикует оси/кнопки и читает эффекты через файл
`/tmp/moza-ac-<uid>/ffb-v2.bin`, доступный только текущему пользователю.
Одновременно разрешён один экземпляр моста. При отключении R5 процесс завершает
эффекты; при устаревании данных игры на 250 мс подаёт нулевую силу. Аппаратный
эффект конечный (1000 мс), поэтому не должен остаться бесконечным при аварийном
завершении процесса. По умолчанию CLI использует 25% (`--gain 0.25`), допускается `--gain 0…1`.
По явному запросу владельца ярлык настроен на 100% (`--gain 1`), с плавным
нарастанием за две секунды после запуска. Аппаратные serial-настройки базы мост не меняет.
Первый вариант с продлением эффекта каждые 50 мс давал слабую вибрацию; теперь
величина загружается до старта и эффект продлевается реже.

Проверено в установленной игре: DirectInput перечисляет MOZA R5 Bridge, успешно
создаются ConstantForce и Damper, газ/тормоз/руль поступают в физику игры, игра
загружает кнопки лепестков 12/13. Владелец подтвердил работу лепестков и наличие отдачи, но на 25% она слишком
слабая для оценки качества. По его запросу включены 100%; качество и направление
на полной силе пока не подтверждены. Успех IOHID-вызовов сам по себе этого не доказывает.

Настройки перед первичной правкой сохранены рядом в `*.before-moza` в папке cfg.
Повторный установщик сохраняет предыдущие файлы в `build/ac-backups/` вместе с
предыдущим значением override. Чтобы удалить интеграцию, при закрытой игре убрать
нашу DLL, восстановить старую DLL (если была), вернуть профиль controls.ini и
прежний override из резервной копии. Базу этот откат не перенастраивает.

Для `swift test` требуется XCTest из полного Xcode. В среде только Command Line
Tools скрипт `check-ac-bridge.sh` запускает те же семь нативных тестов через небольшой
адаптер assert; C-часть проверяется с AddressSanitizer и UndefinedBehaviorSanitizer.

Источники:
- https://github.com/0xbiel/crossover-ffb — COM/DirectInput и общая память (MIT).
- https://github.com/JacKeTUs/universal-pidff — порядок загрузки PID-эффектов.
- https://learn.microsoft.com/en-us/previous-versions/windows/desktop/ee416601(v=vs.85) — семантика DICONDITION.
- Профили `cfg/controllers/presets` установленной игры — формат осей и назначений.


### Запуск на внешнем мониторе

`play-assetto.command` запускает `moza-display-launcher.exe`, который выбирает
неосновной монитор через EnumDisplayMonitors. Первое отображение окна скрыто
через STARTF_USESHOWWINDOW до позиционирования. Затем окно acs.exe занимает полный
прямоугольник внешнего экрана, без рамок и заголовка. Эксклюзивный FULLSCREEN в
video.ini отключается: он выбирал встроенный дисплей Wine. Это полноэкранное окно
на отдельном мониторе, а не отдельный macOS Space. Основной дисплей macOS не меняется.

В этой конфигурации Wine сообщает: встроенный экран (0,0) 1512×982, Samsung
(1512,-98) 1920×1080. Геометрия окна подтверждена через GetWindowRect и записана
в `moza-display.log` рядом с acs.exe. Лаунчер сопровождает только свой дочерний
процесс и не перемещает окна других программ.

Если внешний экран подключён после старта бутылки, Wine может видеть только
встроенный. В этом случае лаунчер завершится с кодом 4, чтобы не открыть игру
на неверном экране. Нужно перезапустить бутылку с подключённым внешним монитором,
запустить Steam и повторить запуск ярлыком. Если Steam ещё не запущен или не
закончил вход, сначала дождаться его готовности: acs.exe иначе возвращает запуск
в Steam и завершается.


## MOZA Paddock — нативный мини-менеджер Assetto Corsa

Сборка: `./Scripts/make-paddock-app.sh release`.
Приложение: `build/MozaPaddock.app`; на рабочем столе есть ярлык **MOZA Paddock.app**.
Это отдельное окно SwiftUI, прежняя утилита строки меню MOZA Control сохраняется.
Приложение использует проект и CrossOver на этом Mac; переносить одну .app на другой
компьютер без проекта и настроенной игры нельзя.

Возможности:
- библиотека установленных автомобилей с поиском, превью и ливреями;
- трассы и конфигурации, локальные автомобильные сетапы из `Documents/Assetto Corsa/setups`;
- тренировка, быстрый круг, гонка с AI, дрифт и Time Attack; для AI проверяется fast_lane.ai;
- погода, время, температура, помощники, количество кругов и соперников;
- живые оси R5, назначение кнопок следующим нажатием, сброс и переназначение;
- синхронный угол базы и игры, усиление отдачи 0–100%; настройки применяются перед стартом;
- именованные пресеты, отдельные снимки конфигурации для результатов;
- установка ZIP / 7z / поддерживаемых libarchive RAR и папок с полными машинами/трассами;
- автоматические лучшие круги игры, история завершённых кругов и экспорт JSON.

Заезды запускаются на внешнем экране через прежний borderless-лаунчер. Steam при
необходимости запускается автоматически; если клиент потребует вход, пользователь
входит в его окне и повторяет запуск. Перед установкой модов или сменой физического
угла текущий заезд необходимо завершить кнопкой приложения.

Хранилище: `~/Library/Application Support/MozaPaddock/paddock.json` (атомарная запись).
Пресеты и черновик сохраняются между запусками. У каждой сессии есть собственный
неизменяемый снимок конфигурации и PID игры: изменение UI не переписывает историю.
Рекорд сравнивается по SHA-256 полного снимка настроек. Переименование пресета
не меняет снимок; обновление его настроек создаёт отдельную группу для сравнения.

Запись времени идёт из оригинального `Local\acpmf_graphics`. DLL копирует 296 байт
в зарезервированный блок общей памяти с offset 6144 (seqlock, timestamp, PID,
данные с +32). Поля completedLaps/iCurrentTime/iLastTime/iBestTime лежат по
смещениям 132/140/144/148 оригинальной структуры. Личный рекорд берётся из
**iBestTime самой игры**, а не из предположения, что любой круг засчитан.
Остальные времена подписаны как не имеющие подтверждённого статуса зачёта.
Paddock должен работать во время заезда; окно можно свернуть. При повторном
открытии во время того же заезда запись продолжается без дублей.

Моды распаковываются во временную папку и проверяются до установки. Пути с `..`,
абсолютные пути, ссылки и специальные файлы отклоняются. Лимит: 100 000 файлов,
25 ГБ распакованных данных. Предыдущие версии пакетов сохраняются в `ModBackups`
в хранилище приложения; при ошибке копирования выполняется откат. Скины отдельно,
CSP, исполняемые установщики и приложения не устанавливаются. Зашифрованные и
неподдерживаемые разновидности архивов завершаются ошибкой. Файлы из модов не
исполняются установщиком. Исходные архивы не изменяются.

Проверки без изменения живого конфига и без команд железу:
```bash
.build/release/MozaPaddock --self-test
python3 Scripts/check-paddock-mods.py
./Scripts/check-ac-bridge.sh
```
Самопроверка Paddock использует временную папку: INI, режимы/AI, кнопки, пресеты,
дедупликация кругов, изоляция PID, восстановление записи и сканирование библиотеки.
Установщик проверен на ZIP, 7z, libarchive, опасных путях/ссылках и откате при
имитации ошибки диска. На реальной игре проверены запуск из UI, R5, внешний экран,
