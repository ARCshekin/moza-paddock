# Участие в разработке

Прочитайте [архитектуру](docs/architecture.md) и [процесс разработки](docs/development.md).

1. Обновите `main`, создайте `feat/<name>` для новой возможности.
2. Ограничьте изменение одним модулем или явно опишите затронутые границы.
3. Выполните подходящие офлайн-проверки; аппаратные проверки указывайте отдельно.
4. Обновите документацию поведения, ограничений и установки.
5. Коммит: `<type>(<part>): <description>`. Откройте pull request с результатами проверок.

Не включайте игровые файлы, Wine prefixes, настройки аккаунтов, токены, логи или скачанные бинарные зависимости. Используйте фикстуры для CI. Версии внешних загрузок закрепляйте с SHA-256 и лицензией.
